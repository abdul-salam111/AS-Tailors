SECRETS AND ENVIRONMENT VARIABLES

Secrets such as the API base URL, the static app token, and any future
key are never typed as literal strings in the source code. They live in
a gitignored .env file and get compiled into an obfuscated Env class by
envied_generator at build time.

File layout:

.env.example  - committed, the template of keys a fresh clone needs
.env          - gitignored, your real local values, never committed
lib/core/constants/env.dart    - the @Envied class, committed, defines
                                  the field names
lib/core/constants/env.g.dart  - generated, gitignored (see below),
                                  obfuscated at build time


FIRST-TIME SETUP AFTER CLONING

On macOS or Linux:
  cp .env.example .env

On Windows PowerShell:
  Copy-Item .env.example .env

Then fill in real values inside .env, and run:
  dart run build_runner build --delete-conflicting-outputs


ADDING A NEW SECRET

1. Add the key to .env.example with a placeholder value, and to your
   own .env with the real value.

2. Add a matching field to lib/core/constants/env.dart, for example:

   @EnviedField(varName: 'NEW_KEY')
   static final String newKey = _Env.newKey;

3. Regenerate by running:
   dart run build_runner build --delete-conflicting-outputs

4. Read it anywhere in the app via Env.newKey, the same way baseUrl and
   appToken already work in ApiEndPoints.


WHY env.g.dart IS THE ONE GENERATED FILE THIS TEMPLATE DOES NOT COMMIT

Everything else this template generates, such as .freezed.dart files,
.g.dart files, and lib/l10n/generated, is committed, following this
repo's usual convention. env.g.dart is the one exception, because it
embeds your own .env values, obfuscated with a per-build key, not
shared secrets that every clone should reuse. Committing it would
either leak real secrets, if you filled in real values, or silently
ship empty ones, if you didn't. Neither is what the next developer who
clones this repo wants baked into their build.


IF .env IS MISSING ENTIRELY

build_runner fails loudly and specifically with a message like this:

  Environment variable not found for field `baseUrl`.

That is the expected and intended failure. It means you skipped the
cp .env.example .env step above, not that something is broken.


IF YOU JUST CREATED .env AND build_runner STILL FAILS THE SAME WAY

The incremental build cache is stale from the earlier failed run. Run
dart run build_runner clean once, then rebuild.


GOOGLE/APPLE SIGN-IN

GOOGLE_SERVER_CLIENT_ID is the one Google credential that lives in .env
(a Web-type OAuth client ID from Google Cloud Console — not the Android
or iOS client). It's not secret in the usual sense (client IDs are
public by design), but it follows the same .env pattern as everything
else here for consistency. You also need to:
  1. Enable the Google provider in Supabase Dashboard > Authentication
     > Providers, with that same client ID and its secret.
  2. Enable the Apple provider there too, with your Services ID /
     Team ID / key from Apple Developer (Sign In with Apple capability).
  3. Add the platform-specific config neither .env nor Supabase cover:
     Android's SHA-1 fingerprint registered with the Google client,
     iOS's URL scheme / reversed client ID in Info.plist, and the
     "Sign In with Apple" capability in the Xcode project.
Until all of that is done, the Google/Apple buttons render correctly
but fail with a clear error on tap rather than crashing anything.


CI/CD

Write .env from your CI secret store as a build step before running
build_runner, for example:
  echo "$ENV_FILE_CONTENTS" > .env
in GitHub Actions. Never commit a real .env to work around this.


NON-SECRET ENVIRONMENT FLAGS

For a build-time flag that isn't a secret, such as which named
environment you are targeting, --dart-define is still the right tool.
It is visible in plaintext in build logs and CI configuration, which is
fine for a flavor name but not for a token.

  flutter run --dart-define=ENV=staging

Read it in Dart with:
  const env = String.fromEnvironment('ENV', defaultValue: 'dev');
